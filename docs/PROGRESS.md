# 진행 기록과 결정 이유

이어받는 사람(또는 AI)이 "왜 이렇게 했는지" 알 수 있도록, 진행 순서대로 바뀐 결정과 그 이유를 적었습니다.

## 1. 방향 전환: 직접 만든 교착 → 검증된 자율주행에서 생기는 교착

- 처음엔 CARLA 기본 자율주행에 고정값·하드코딩으로 교착을 만들었음.
- 문제 ① LLM은 답 하나에 수 초 → 1초 안에 반응해야 하는 상황(교차로 충돌 등)엔 못 씀.
- 문제 ② 억지로 만든 교착은 비현실적이고, 단순 규칙으로도 풀려 LLM이 필요 없었음.
- → 공개된 고성능 전문가 주행 **PDM-Lite(carla_garage)**를 그대로 쓰고, 그것조차 못 푸는 상황을 찾기로 함.

## 2. PDM-Lite 관찰에서 얻은 사실

- PDM-Lite는 시나리오가 `CarlaDataProvider.active_scenarios`에 **장애물로 등록한 것만** 우회함.
- 같은 위치의 같은 차라도 등록하면 17초 만에 우회(165), 안 하면 180초 대기 후 실패(165_broken).
- 등록 안 된 정적 물체(상자, 라바콘)는 아예 무시하고 충돌함.
- → LLM의 역할 = 상황을 해석해서 "이건 장애물로 등록하라 / 기다려라"를 정하는 것. 실제 우회는 PDM-Lite에 맡김.

## 3. 시나리오 3종 재정립

| | 시나리오 | LLM 호출 | 비고 |
|---|---|---|---|
| ① | 앞차 정지 (고장차·정지차 vs 대기열·정체·신호) | GRU | 중심 실험, 검증 완료 |
| ② | 낙하물 | 물체 감지 | 1차 결과 |
| ③ | 공사 임시 통로 (지도에 없는 길) | 콘 감지 | 1차 결과 |

9/30 진행보고서의 ③ "무신호 교차로 비보호 좌회전"은 PDM-Lite가 1초 안에 충돌하는 빠른 상황이라 LLM이 낄 수 없어서 공사 임시 통로로 바꿈.

## 4. GRU: 바뀐 결정들

1. **첫 라벨 (`--label p`)**: 고장차·정지차 판에서 1초 이상 정지 = 1. 결과가 너무 좋았음(0.9초, 오경보 0).
2. **지름길 발견 (`--drop front2`)**: '그 앞차' 정보를 빼자 6.1초로 늦어지고 오경보 발생. 대기열 판에만 앞차 뒤에 차가 한 대 더 보였고, GRU가 "차 두 대 = 대기열"을 외운 것.
    - 대응: 대기열 1~3대 랜덤, 정지차 앞에 50% 확률로 차 한 대 더.
3. **라벨 재정의 (`--label long`)**: 시나리오 종류 대신 "빨간불 아닌데 12초 이상 이어질 정지"를 1로. GRU는 교착을 단정하지 않고 "물어볼 만한 정지"를 고르고, 의미 판단은 LLM이 함 (긴 대기열이면 LLM이 WAIT).
4. **도로 일반화**: 165번 도로만 학습하면 새 도로에서 5초 규칙 수준. 도로 4곳(165, r157, r174, r180)으로 늘리고 도로별 교차 검증 도입.
5. **헛호출 검증**: 1.7초 만에 부르는 건 "앞 정지차 + 빨간불 아님 = 일단 부르기"를 배운 것. 일상 정체가 데이터에 없어 안 드러났음 → 짧은 대기열(1~5초)·정체(StopAndGo) 추가 (풀리는 정지 14 → 44건).
6. **기억 길이 3초 → 20초 (`--win-sec 20 --hz 4`)**: 3초로는 정체 속 정지와 고장차 뒤 정지의 시작이 같음. 20초로 늘리자 호출 12.2초 → 6.4초, 정체 헛호출 0.
7. **기준값 0.85 → 0.99 + 12초 안전장치**: 헛호출 비용(C)을 놓고 총비용이 가장 작은 조합 선택 (`gru/tradeoff.py`). 출력이 0/1로 몰려 기준값에 따른 차이는 작음.

## 5. 통합과 최종 테스트

- LLM 자리는 같은 JSON 형식으로 답하는 대체 응답기 (비상등 ON 또는 앞차 30초 이상 정지 → BYPASS). Claude API 연결 코드는 있으나 비용 문제로 미사용.
- 줄지어 선 차(정지차 + 그 앞 주차차)는 맨 끝 차까지 한 번에 등록 (`_stopped_chain_end`).
- 배경 교통이 시나리오 차와 자차 사이에 끼는 문제 → `ClearEgoLaneAhead` (자차 차선만, 시나리오 차 20m 앞에서 멈춤. 처음엔 우회 중인 옆 차까지 지워서 수정함).
- Town04 15판 최종 테스트: 15/15, 충돌 0 (`results/final_test/`).

## 6. 확장 시나리오에서 배운 것

- **낙하물**: 처음엔 물체 크기·이름을 시뮬레이터가 정확히 알려줌 → `-Perception noisy` 추가 (크기에 따라 25~50m에서야 보임, 크기 ±30%, 이름 모름).
- 커브에서 물체를 늦게 감지하던 버그 → 차선을 따라가며 같은 차선인지 판단하도록 수정.
- 옆 차선이 꽉 찬 상황에서 끼어들기 확인 코드를 직접 추가했다가 PDM-Lite 자체 판단과 충돌해 오히려 나빠짐 → 기본 꺼둠 (`SAFE_MERGE=0`). 실행은 PDM-Lite에 맡기는 원칙 유지.
- **공사 통로**: 배경 차가 콘 사이에 끼어 실험을 망침 → `-NoTraffic` (배경 교통 없음) 추가.

## 7. 날씨 설정

- 초기 단계라 **모든 루트를 맑은 낮**(구름 5%, 비 0, 태양 고도 70°)으로 통일함. 카메라 사진을 LLM에게 보여줄 때 잘 보이는 조건에서 먼저 확인하기 위해서.
- 그 전 실험(GRU 데이터 수집, 최종 테스트)은 원래 루트의 날씨(일부 밤·비)로 돌았음. GRU 입력은 시뮬레이터 정보라 날씨 영향이 없음.
- 원래 날씨의 루트 파일은 `leaderboard/data/bench2drive_split/_weather_backup/`에 보관.

## 8. 남은 일

1. 실제 LLM 연결, 카메라 사진으로 비상등 없는 정지차 구분
2. LLM 출력을 제어로 옮기는 방식 다듬기 (조건부 지시 등)
3. 시나리오별 반복 실행으로 성공률 통계
4. 12초 근처 애매한 정지(8~16초 대기열) 데이터 추가, 확률 보정
5. 인식 오류를 넣은 CSV로 GRU 견고성 확인
6. (시간 되면) 센서 기반 TransFuser++에 적용
